# CrackHash

## Описание проекта

**CrackHash** - распределённая система для подбора строк по их MD5-хэшу методом полного перебора (brute-force).

Система построена по архитектуре **manager-worker** и состоит из компонентов:

- **Manager** - принимает запросы, разбивает задачу на части, отправляет воркерам и агрегирует результаты
- **Worker** - перебирает строки и вычисляет их MD5
- **RabbitMQ** - транспорт между Manager и Worker (очередь задач и очередь результатов)
- **MongoDB Replica Set** - хранение состояния запросов и подзадач (1 primary + 2 secondary)

## Как работает система

1. Клиент отправляет MD5-хэш и максимальную длину строки в Manager
2. Manager создаёт уникальный `requestId`
3. Пространство поиска делится на части по количеству воркеров
4. Manager сохраняет запрос и подзадачи в MongoDB
5. Подзадачи публикуются в RabbitMQ (tasks queue)
6. Воркеры забирают задачи из очереди, перебирают комбинации и ищут совпадения
7. Результаты публикуются в RabbitMQ (results queue)
8. Manager считывает результаты, обновляет состояние в MongoDB
9. Клиент получает статус задачи по `requestId`

- Отслеживание статуса по `requestId`

- Git

```bash
git clone <your-repo>
cd crack-hash
docker compose -f docker-compose.yml up -d --build
```

```bash
docker exec -it mongo1 mongosh --eval "rs.status().members.map(m => ({name:m.name,stateStr:m.stateStr}))"
```

- URL: `http://localhost:15672`
- login/password: `guest / guest`

## Client API

### Создание задачи

POST `/api/hash/crack`

```json
{
  "hash": "5d41402abc4b2a76b9719d911017c592",
  "maxLength": 5
}
```

Ответ:

```json
{
  "requestId": "uuid"
}
```

------------------------------------------------------------------------

### Проверка статуса

GET `/api/hash/requestStatus?requestId=<uuid>`

Статусы:

`IN_PROGRESS` - выполняется  
`READY` - завершено  
`PARTIAL_RESULT` - частичный результат  
`ERROR` - ошибка

------------------------------------------------------------------------

## Messaging (RabbitMQ)

### Manager -> Worker (задачи)

- Exchange: `crackhash.tasks.exchange` (`direct`)
- Queue: `crackhash.tasks.queue`
- Routing key: `crackhash.tasks.routingKey`

### Worker -> Manager (результаты)

- Exchange: `crackhash.results.exchange` (`direct`)
- Queue: `crackhash.results.queue`
- Routing key: `crackhash.results.routingKey`

Сообщения отправляются как **persistent**.

------------------------------------------------------------------------

## Архитектура

- Manager распределяет задачи через RabbitMQ
- Воркеры работают независимо и обрабатывают задачи из очереди
- Результаты собираются асинхронно
- Состояние задач хранится в MongoDB
- При сбоях применяется повторная доставка и recovery зависших подзадач
